**Operator 0.19.0 — quitting works, dev servers stop leaking, and the Inbox is now a log.**

- **The quit dialog no longer freezes the app.** "N agents are still working" was drawn with no
  parent window, which on macOS runs a nested modal loop on the UI thread — every window stopped
  painting until it was answered. It is now a sheet on the window, and the window is raised first
  so it cannot be asked from behind another app. A slow renderer could also leave two copies of
  that dialog on screen whose answers disagreed; the first answer now wins and the second is
  dropped, so "Stay open" can no longer be overridden into a quit.
- **Dev servers die with the lane, the session and the app.** A server the agent started in the
  background reparented away from its terminal the moment the shell that launched it exited, so
  closing the lane never reached it. 24 were found alive on one machine, the oldest 11 days, one
  holding a port since Aug 20 and blocking new lanes from starting. Closing a lane, closing a
  project, and quitting now each end the servers that lane started — matched by the tag Operator
  puts in their environment, never by name, so other projects' servers are left alone.
- **The Inbox is gone; the Comms log replaces it.** Reports now appear on their task card and in
  one per-project timeline alongside dispatches and the replies that were blocked, instead of in
  a mailbox with an unread badge. The read receipt went with it: the reader is usually an agent,
  so it measured an automated open while looking authoritative.
- **Reports stop landing in the wrong project.** One database holds every project on the machine
  and the queue was filtered only by role, so the first idle coordinator drained another repo's
  reports — and because delivery is stamped exclusively, the real recipient was never told at
  all. Lanes now carry their project and role in their own environment rather than having them
  guessed from a terminal id that several sessions share.
