# Chat renders Claude Code's plumbing as if the user typed it

**Reported:** 2026-07-28, live session, timestamps 10:17.
Screenshot: `/tmp/operator-shots/2026-07-28-injected-turns.png`

Four consecutive turns, all labelled **YOU** with the user dot, none typed by the user:

```
YOU  <local-command-caveat>Caveat: The messages below were generated by the user while
     running local commands. DO NOT respond to these messages…</local-command-caveat>
YOU  <command-name>/model</command-name>
       <command-message>model</command-message>
       <command-args>sonnet</command-args>
YOU  <local-command-stdout>Set model to ␛[1mSonnet 5␛[22m and saved as your default…</local-command-stdout>
YOU  hi
```

Only the last one is the user.

## The filter already exists and is already correct — it is simply not wired to chat

`transcript.rs:639` `is_injected_turn()` matches exactly these prefixes:
`<local-command-`, `<command-name>`, `<command-message>`, `<command-args>`, `<system-reminder>`,
`<task-notification>`, `<synthetic>`.

It is applied at `transcript.rs:260` — **only to the session summary guard**:

```rust
if self.summary.is_none() && !is_injected_turn(&text) { … }   // titles only
```

`push_narration(NarrationEntry { kind: "user", … })` at `:277` sits **outside** that guard, so every
injected turn still flows into the chat panel. The filter was written to stop ugly
`"<local-command-cavea…"` session titles and was never extended to the narration path.

Same story on the renderer: `lib/format.ts:53` exports `isInjectedTurn`, and it is unit-tested
against **the exact strings in this screenshot** (`format.test.ts:77-80`). Its only caller is
`session-label.ts` — naming sessions. `CanvasConversation` never calls it.

So both halves exist, both are tested, and neither guards the reading surface.

## Fix

1. **Stop rendering injected turns as user prose.** Apply the existing filter on the narration path.
   Prefer fixing it in `transcript.rs` so the junk never reaches `chat.db` — note the existing
   entries are already persisted, so the renderer needs the guard too for history already on disk.
   Keep the two prefix lists in sync; the comment at `:637` already says so.
2. **Do not simply delete slash commands from the record.** `/model sonnet` → *"Set model to
   Sonnet 5"* is real session history and belongs in a structured transcript — as a **command
   block** (command + args + its output, collapsed), not as a fake user turn. This is a natural
   first block kind for the structured-transcript work, and it needs no new event source: the data
   is already in the JSONL. `<system-reminder>` / `<synthetic>` / `<local-command-caveat>` are pure
   plumbing and should just be dropped.
3. **Strip ANSI escapes from command output.** `<local-command-stdout>` carries raw SGR codes —
   `␛[1m` / `␛[22m` render as replacement glyphs plus literal `[1m`. Anything that reaches the chat
   surface must be ANSI-stripped (or converted, since `[1m`/`[22m` is just bold). This will matter
   for every tool-output block in the structured-transcript build, so put it somewhere reusable
   rather than inline.

## Note on scope

This is chat-fidelity work and overlaps `dev/briefs/chat-signals-and-interrupt.md`. The filter fix
(1) and the ANSI strip (3) are small and independent — do them with the signals task. The command
block (2) belongs to the structured-transcript build.
