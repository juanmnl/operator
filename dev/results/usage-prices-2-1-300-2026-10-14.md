# Usage prices from Claude Code 2.1.300, and skipping `api-request` records (2026-10-14)

Brief: audit report #2369 (`dev/results/claude-code-updates-audit-2026-10-14.md`), items 1, 3, 5 and 6.
Branch `operator/f25fc0`, based on main `b8ae343`.

## What changed

`electron/src/main/usage.ts`

- `rates(model, fast, promptTokens)` has explicit rows ahead of the substring fallbacks, most specific first:
  - `haiku-5-5`: 0.10 / 0.50, cache read 0.01. Above 100,000 prompt tokens (input + cache read + cache write, strict `>`): 0.50 / 2.50, cache read 0.05.
  - `fable-5-1` and `mythos-5-1`: 10 / 50, cache read 0.25.
  - `opus-5-5`: 4 / 20, cache read 0.20. Fast: 8 / 40, cache read 0.40.
  - `sonnet-5-5`: 2 / 10, cache read 0.10.
  - Opus 4.0 and 4.1 (`opus-4-1`, or `opus-4` not followed by a single-digit segment, which is Claude Code's own regex): 15 / 75. Fast: 30 / 150.
- Opus fast mode in the fallback: `opus-5*` and `opus-4-8` take 10 / 50, any other Opus 30 / 150. Before, every Opus fast turn was 10 / 50.
- `cost()` passes `r.context` (input + cache read + both cache writes) as `promptTokens`.
- The "Mythos 5.1 is open" comment is replaced with the source and date.
- New export `isApiRequestLine(line)`: `line.startsWith('{"type":"api-request')`. The scan loop skips those lines before `JSON.parse`.

`electron/src/main/transcript.ts`: `poll()` skips the same lines before `JSON.parse`. The byte offset still advances past them.

Cache-write multipliers in `cost()` (1.25x and 2x input) are unchanged. They hold for every tier in the catalog, including the Haiku 5.5 long-prompt tier (0.625 / 1.00) and every fast tier.

## Price sources

All read from the installed binary `~/.local/share/claude/versions/2.1.300` (`claude --version` = 2.1.300), using `strings`:

- `PMr.pricing_tiers` (the baked model catalog, `schema_version: 1`) and the `pricing` key on each `models[]` entry. Mapping read out:
  `claude-haiku-5-5` → `haiku_55`; `claude-haiku-4-5` → `haiku_45`; `claude-sonnet-5-5` → `tier_2_10_cache_read_0_10`; `claude-sonnet-5` → `tier_2_10`; `claude-sonnet-4-*` → `tier_3_15`; `claude-opus-5-5` → `tier_4_20_cache_read_0_20`; `claude-opus-5`, `4-8`, `4-7`, `4-6`, `4-5` → `tier_5_25`; `claude-opus-4-1`, `4-0` → `tier_15_75`; `claude-fable-5`, `claude-mythos-5` → `tier_10_50`; `claude-fable-5-1`, `claude-mythos-5-1` → `tier_10_50_cache_read_0_25`.
- `haiku_55.long_prompt`: `above_prompt_tokens: 1e5, input 0.5, output 2.5, cache_write_5m 0.625, cache_write_1h 1, cache_read 0.05`. Applied by `lI()`: `input_tokens + cache_read_input_tokens + cache_creation_input_tokens > abovePromptTokens`.
- Fast mode, `tNt()` (the cost lookup), when `speed === 'fast'`: `claude-opus-5-5` → `Uy` (8 / 40, cache read 0.4); `claude-opus-4-8`, `claude-opus-5` → `Sa` (10 / 50, cache read 1); `claude-opus-4-6`, `claude-opus-4-7` → `Ny` (30 / 150, cache read 3). `Jft()` returns `Ny` for any other Opus; that is what `usage.ts` does for an Opus outside the list.
- Model-id canonicalisation, `_L()`: plain `includes()` checks in the order fable-5-1, fable-5, mythos-5-1, mythos-5, opus-5-5, opus-5, opus-4-8 … opus-4-1, then `/claude-opus-4(?!-\d(?!\d))/` for 4.0. `usage.ts` follows the same order.

Research's numbers in the brief all match the binary. One refinement: "other Opus 30 / 150" in fast mode is, in `tNt()`, specifically Opus 4.6 and 4.7.

## Timings

Machine: this Mac, Node v26.8.2, cold module and empty usage cache per run, `~/.claude/projects` = 8,089 top-level `.jsonl` files, 4.74 GB.

Full scan (`computeUsage(0)`), alternating runs:

| Run | Before | After |
|-----|-------:|------:|
| 1 | 12,809 ms | 12,877 ms |
| 2 | 13,299 ms | 13,266 ms |
| 3 | 13,111 ms | 13,277 ms |

No measurable difference today. The reason: 2.1.300 landed today, so only 6 of 8,089 files contain `api-request` records: 534 lines, 7 MB, 0.16% of bytes. Time split for one full scan: read 2,471 ms, `split('\n')` 2,489 ms, `JSON.parse` of other lines 4,707 ms, `JSON.parse` of `api-request` lines 13 ms, the prefix test on every line 23 ms.

On the 6 files that do carry the records (13.9 MB, 55% of it `api-request*` bytes), split + parse, 10 iterations after warm-up, three runs: 28.8 / 28.5 / 29.0 ms without the skip, 15.4 / 15.3 / 15.2 ms with it, about 47% less. Per byte, `api-request` lines parse about 1.3x slower than the rest (13.4 ms for 7.6 MB against 8.1 ms for 6.1 MB). As 2.1.300 transcripts accumulate, the saving on the parse share of the scan should approach that 47% on new files. The prefix test costs about 23 ms per full scan.

## Behaviour change in the tailer

Before, an `api-request` line went through `apply()`. Its `timestamp` set `lastActivityAt`, and because it has no `isSidechain`, it would have ended an open sidechain ("Subagent finished") if one were in progress. With the skip, neither happens. The `user` or `tool_result` record written just before each request still sets `lastActivityAt` at about the same moment.

## Left out

- Claude Code multiplies the whole cost by 1.1 when `usage.inference_geo === 'us'` (`aI()`). Not implemented: across the 60 most recent transcripts every value is `global` (11,093) or `not_available` (469).
- Haiku 3.5 (0.80 / 4) and the Claude 3 models still fall to the family fallbacks. Haiku 3.5 is over-reported by 25%, which is the pessimistic direction.
- Web-search request pricing ($0.01 each) is not counted; `usage.ts` never read `server_tool_use`.
- Not built, recommended to the coordinator: `usage.ts` reads only `~/.claude/projects/<slug>/*.jsonl`, not the subagent transcripts under `<slug>/<session>/subagents/*.jsonl`. On this machine that is 678 MB in 326 files that carry `usage`, 87 of them modified since 2026-10-01. Subagent spend is therefore missing from the Usage and Tuning pages. This needs a Code task, with Research first confirming whether those records also appear in the parent file (the de-duplication key would catch an overlap).
