**What the brief asked for that this tooling cannot do.** `scripts/visual/` has exactly two
harness pages — `index.html` (raw xterm glyphs) and `chat.html` (lane-identity swatches) — neither
renders the app shell, so there is no headless path to a toolbar frame, the Files view, or the
preview toolbar. There is also no contrast-checking script anywhere in the repo. This is not a gap
I introduced by scoping down; it's the same gap `dev/results/code-navigator-s1-s4.md` already
flags under **Not verified**: *"Nothing has been seen on screen … check `--yellow` and `--green`
on the three LIGHT palettes, which is where every previous ink in this app has failed its contrast
floor."* That eyeball check was requested and never done, headless or otherwise.

**So I computed it directly instead of skipping it.** The code viewer's background is
`transparent` in `cm-theme.ts`; its actual painted background is `var(--bg-terminal)`, set on the
Files-view container at `DashboardView.tsx:4394`. Pulled the real hex values from
`src/renderer/themes/*.ts` and ran WCAG 2.1 contrast (formula sanity-checked: black/white = 21.00,
matches spec exactly):

| Palette | bg (`--bg-terminal`) | `--yellow` | ratio | `--green` | ratio |
|---|---|---|---|---|---|
| mission-control-light | `#F6F8F7` | `#b8860b` | **3.05:1 FAIL** | `#0ca678` | **2.92:1 FAIL** |
| mr-pink-light | `#F8F6F8` | `#b8860b` | **3.03:1 FAIL** | `#27ae60` | **2.67:1 FAIL** |
| 1984-light | `#e4e5f5` | `#FF8D01` | **1.86:1 FAIL** | `#00af4f` | **2.32:1 FAIL** |

**All six fail the 4.5:1 floor**, 1984-light's `--yellow` badly (1.86:1 — barely above pure
decoration). This is the number-literal and string-literal ink in every syntax-highlighted file a
user opens on a light palette. Confirmed real: these are the same `--yellow`/`--green` tokens
`cm-theme.ts` maps `t.number`/`t.string` to, on the same background the Files view actually paints
behind them — not a hypothetical combination.
