## N1 (Review's verdict, blocker): the lane was stopped before merge could refuse — a550eed

| Finding | Fix |
|---|---|
| N1: the Diff panel killed its lane (`lane-merge.ts:33`), and only then did `mergeBranch`/`discardBranch` run their refusals (another live terminal, a dirty source repo, a missing branch). A refused merge stopped the lane for nothing. | The order moved into main, so nothing can happen between the check and the action. `mergeBranch` now does, in order: (1) the live-lane refusal; (2) both branches exist; (3) the source-repo check below; (4) switch the source repo to the base branch; (5) **only then** call `stopLane` (IPC: `terminals.kill(ownTerminalId)`); (6) commit the worktree when a `commitMessage` is given; (7) merge. `discardBranch` refuses first and stops the lane after. A refusal returns before `stopLane`, so the lane keeps running, untouched. The panel makes one call (`worktreeMerge(…, ownTerminalId, commitMessage)`) and no longer kills or commits itself; `lib/lane-merge.ts` is a thin wrapper. |
| Related: untracked files in the source repo blocked every merge. | A tracked change (any status other than `??`) still blocks, and the message names the files. An untracked file blocks only when the merge would write that path: `git diff --name-only <base>...<branch>`, plus the worktree's uncommitted files when a commit message says they will be committed. The message names the clashing paths. |

**Commit is opt-in.** Main commits only when the caller passes a commit message. The Diff panel always does; the Task board commits on its own first and passes none. Without a message, the path set leaves out the worktree's uncommitted files, because they are not merged. A worktree still dirty after the merge is kept, as in 57db346.

**Tests** (`electron/src/main/worktree.test.ts`, "refusals leave the lane running"; `stopLane` is a spy):
- refused because another live lane is in the worktree: not stopped;
- refused because of a tracked change in the source repo: not stopped;
- refused because the branch is missing: not stopped;
- an untracked source file at a path the branch writes: refused, not stopped, and the file is untouched;
- an untracked source file at a path the worktree has uncommitted (to be committed): refused, not stopped;
- an untracked source file the merge does **not** touch: merged. The lane is stopped once, and a file written at the moment it stopped is committed (with the given message) and lands on main;
- a discard refused because a scratch shell is open in the worktree: not stopped, and worktree and branch are kept;
- a discard that goes through: stopped while the folder still exists, then removed.

The old "refuses when the source repo is dirty" test used an untracked file the merge does not touch; it now uses a tracked edit. `lane-merge.test.ts` is rewritten to the one-call shape.
